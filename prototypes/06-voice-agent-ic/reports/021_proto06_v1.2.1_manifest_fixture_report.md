## Structure du manifest

Le fixture `climate-roundtable-demo.json` contient :

- `schema`, `schemaVersion`, `manifestId`, `activityId`, `version`, `status`;
- `prototype.id = "proto06"` et `prototype.minVersion = "1.2.1"`;
- `uiLanguage`, `targetLanguages`, `climateThemes`;
- `characters[]` pour Clara, Marco et Ana;
- `pedagogicalScenario` avec objectif, consigne et question commune;
- `meeting.steps[]` avec trois tours scenarises;
- `review.reviewStatus = "human-reviewed"`;
- `safety` avec `generatedLive=false`, `openAiInLearnerFlow=false`, `containsLearnerText=false`.

Le manifest ne contient ni secret, ni prompt, ni provider IA, ni token de lancement, ni texte apprenant.

## Strategie de chargement

`script-1.2.1.js` lit le parametre URL `manifestId`.

Si `manifestId=climate-roundtable-demo`, le script charge localement :

```txt
data/proto06-manifests/climate-roundtable-demo.json
```

Le chargement est volontairement local et synchrone, dans l'esprit du chemin V1.2 existant qui initialise la rencontre avant le rendu. Cette solution reste limitee a un fixture et pourra etre remplacee par un chargement asynchrone propre lors d'un palier Hub ulterieur.

## Strategie de validation

Validation navigateur ajoutee :

- schema attendu : `ic-lab-proto06-activity-manifest`;
- presence de `schemaVersion`;
- `status` limite a `published` ou `human-reviewed`;
- `prototype.id === "proto06"`;
- presence de `characters[]`;
- presence de `meeting.steps[]`;
- chaque step doit avoir `characterId`, `text`, `languageId`;
- chaque step doit avoir `generated === false`;
- chaque step doit avoir une source de type `human-reviewed`;
- `safety.generatedLive === false`;
- `safety.openAiInLearnerFlow === false`;
- `safety.containsLearnerText === false`.

## Comportement avec manifest valide

Avec :

```txt
http://127.0.0.1:8788/index-1.2.1.html?manifestId=climate-roundtable-demo
```

Prototype 06 construit la rencontre depuis le manifest :

- titre et objectif depuis `manifest.title` et `pedagogicalScenario.pedagogicalGoal`;
- consigne et question commune depuis `pedagogicalScenario`;
- personnages depuis `manifest.characters`, en reutilisant les catalogues locaux pour les assets existants;
- tours de parole depuis `meeting.steps`;
- observation initiale depuis `meeting.initialObservation`;
- runtime conserve : `scripted`.

Aucun texte n'est genere dynamiquement.

## Comportement sans manifest

Si aucun `manifestId` n'est fourni, V1.2.1 suit le comportement V1.2 historique :

Si `manifestId` est fourni mais introuvable ou invalide :

- une carte enseignante indique que le manifest local est indisponible;
- l'erreur de validation est affichee de maniere lisible;
- un lien propose de revenir a `index-1.2.1.html`;
- aucun serveur externe n'est appele sur ce chemin manifest;
- le runtime reste scenarise.
