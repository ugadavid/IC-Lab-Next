## Strategie de chargement Hub

V1.2.3 lit toujours `manifestId` dans l'URL.

Nouveau comportement :

```txt
activitySource=hub-manifest&manifestId=climate-roundtable-demo
```

declenche un chargement synchrone depuis :

```txt
http://127.0.0.1:8790/api/proto06/manifests/climate-roundtable-demo
```

Le choix reste minimal et proche de V1.2.2 : la rencontre est construite pendant l'initialisation, avant le rendu principal, afin de limiter le refactor.

La carte enseignante indique maintenant la source :

```txt
Source : IC-Hub
```

Les badges restent visibles :

- `Activite publiee`;
- `Runtime scenarise`;
- `IA reelle non active`.

## Validation du manifest

La validation V1.2.2 est reutilisee :

- schema attendu;
- status `published` ou `human-reviewed`;
- `prototype.id === "proto06"`;
- `characters[]` present;
- `meeting.steps[]` present;
- chaque step a `characterId`, `text`, `languageId`;
- `meeting.steps[].generated === false`;
- source relue humainement;
- `safety.generatedLive === false`;
- `safety.openAiInLearnerFlow === false`;
- `safety.containsLearnerText === false`.

En cas d'erreur Hub, V1.2.3 affiche une carte claire et ne bascule pas silencieusement vers un autre manifest.
