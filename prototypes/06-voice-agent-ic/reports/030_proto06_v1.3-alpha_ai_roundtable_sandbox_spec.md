# 030 - Prototype 06 V1.3-alpha - Specification operationnelle AI roundtable sandbox

Date: 2026-07-03

## Resume executif

Prototype 06 V1.3-alpha est specifie comme une evolution experimentale de Proto06 V1.2.3, dediee a un bac a sable IA admin-only pour explorer des tours de parole generatifs entre Clara, Marco et Ana.

Cette specification ne decrit pas un nouveau prototype independant. Elle decrit un espace experimental herite de Proto06, separe du parcours etudiant stable valide :

```txt
IC-Hub V0.9.9
-> assignation Proto06
-> index-1.2.3.html
-> manifest Hub climate-roundtable-demo
-> runtime scenarise
-> traces sobres
```

Le sandbox V1.3-alpha sert a concevoir et comparer des brouillons IA. Il ne publie rien automatiquement, ne s'assigne pas a des etudiants, n'ecrit rien dans les `run_events` apprenants et ne modifie pas le manifest publie.

## Heritage Proto06

V1.3-alpha herite de Proto06 V1.2.3 :

- personnages Clara, Marco, Ana ;
- logique de table ronde plurilingue ;
- manifest `climate-roundtable-demo` comme reference ;
- badges de securite ;
- runtime scenarise comme fallback ;
- chargement Hub possible ;
- traces sobres ;
- separation deja validee entre activite publiee et execution etudiante.

Le principe directeur est simple :

```txt
V1.2.3 reste le parcours stable.
V1.3-alpha est un espace de conception experimental.
```

## Objectifs

Objectifs de V1.3-alpha :

- permettre a un admin ou concepteur pedagogique de tester des tours de parole generatifs ;
- garder Clara, Marco et Ana comme personnages de reference ;
- produire des brouillons non publies ;
- comparer ces brouillons aux tours scenarises du manifest ;
- documenter les contraintes utilisees ;
- preparer une eventuelle revue humaine ;
- conserver le runtime scenarise comme sortie stable.

Non-objectifs :

- activer une IA dans le parcours etudiant ;
- remplacer le manifest publie ;
- publier automatiquement un contenu IA ;
- connecter les brouillons aux assignations ;
- stocker les brouillons dans les runs apprenants.

## Ecrans proposes

### 1. Accueil sandbox

Role : poser le cadre et eviter toute confusion avec l'activite etudiante.

Elements visibles :

- titre : `Sandbox IA Proto06 V1.3-alpha` ;
- badge : `Admin seulement` ;
- badge : `Experimental` ;
- badge : `Non publie` ;
- badge : `Ne pas assigner aux etudiants` ;
- rappel : `Generation IA active uniquement dans cet espace` ;
- lien retour vers Proto06 stable ou documentation.

Etat attendu :

- aucune generation au chargement ;
- aucun appel provider sans action explicite ;
- avertissement visible avant tout bouton de generation.

### 2. Selection du contexte

Role : choisir une base de travail controlee.

Champs proposes :

- manifest de depart : `climate-roundtable-demo` ;
- affichage court du manifest :
  - titre ;
  - theme ;
  - consigne ;
  - question commune ;
  - personnages ;
  - langues ;
- choix du mode :
  - `Comparer au manifest publie` ;
  - `Generer une variante brouillon` ;
  - `Tester une reformulation controlee`.

Le manifest complet ne doit pas etre envoye au provider par defaut. L'interface doit afficher un resume court des donnees qui seront utilisees.

### 3. Selection du personnage

Role : limiter la generation a un personnage et une langue cible.

Options :

- Clara :
  - langue cible : espagnol ;
  - role : etudiante ;
  - contexte : Valencia / chaleur ;
- Marco :
  - langue cible : italien ;
  - role : etudiant ;
  - contexte : secheresse ;
- Ana :
  - langue cible : portugais du Bresil ;
  - role : etudiante ;
  - contexte : pluies fortes.

Regle : un seul personnage genere a la fois dans la premiere implementation.

### 4. Consigne de generation

Role : cadrer l'appel IA.

Champs autorises :

- objectif pedagogique general ;
- question commune ;
- theme climatique ;
- contrainte de langue ;
- longueur cible ;
- niveau de difficulte ;
- mots transparents souhaites ;
- tour precedent non apprenant, si utile ;
- ton attendu : temoignage court, oral, accessible.

L'interface doit distinguer :

- donnees envoyees au provider ;
- donnees non envoyees ;
- donnees interdites.

### 5. Generation experimentale

Role : declencher une generation uniquement apres confirmation claire.

Bouton propose :

```txt
Generer un brouillon experimental
```

Avant l'appel :

- rappeler que la sortie n'est pas publiee ;
- rappeler qu'elle doit etre relue humainement ;
- afficher le provider / modele si disponible ;
- afficher `store:false` comme exigence serveur ;
- afficher que le texte ne sera pas ecrit dans `run_events`.

### 6. Zone resultat

Role : inspecter un brouillon IA sans le confondre avec un manifest.

Contenus :

- texte genere ;
- personnage ;
- langue ;
- contraintes utilisees ;
- avertissements ;
- statut : `draft` ;
- `publishable: false` ;
- `reviewStatus: unreviewed-ai-draft`.

Actions possibles :

- copier localement ;
- exporter localement ;
- rejeter ;
- comparer au tour scenarise ;
- marquer pour revue humaine.

Actions interdites :

- publier ;
- assigner ;
- envoyer a un cours ;
- ecrire dans un manifest publie ;
- ecrire dans `run_events`.

### 7. Comparaison avec le manifest scenarise

Role : garder le manifest publie comme reference.

Affichage propose :

```txt
Tour scenarise humain
vs
Brouillon IA experimental
```

Critiques a afficher :

- respect de la langue cible ;
- longueur ;
- clarte ;
- mots transparents ;
- fidelite au theme climatique ;
- risque de sur-explication ;
- risque de confusion interculturelle ;
- besoin de revue humaine.

### 8. Export local

Role : permettre une sauvegarde manuelle hors serveur.

Format : JSON local telecharge cote navigateur, sans upload serveur.

Contraintes :

- export marque `experimental` ;
- `publishable: false` ;
- pas de cle API ;
- pas de token ;
- pas de session ;
- pas de texte apprenant.

## Donnees autorisees vers le provider IA

Les donnees autorisees doivent etre minimales et pedagogiques.

Autorise :

- `sourceManifestId` ;
- titre court du manifest ;
- theme climatique ;
- objectif pedagogique general ;
- consigne generale ;
- question commune ;
- `characterId` ;
- role public du personnage ;
- langue cible du personnage ;
- contexte court du personnage ;
- longueur cible ;
- registre attendu ;
- mots transparents souhaites ;
- tour precedent uniquement s'il vient du manifest publie ou d'un brouillon non apprenant explicitement selectionne ;
- contraintes de securite et de style.

Exemple de contexte autorise :

```json
{
  "sourceManifestId": "climate-roundtable-demo",
  "theme": "constats climatiques",
  "pedagogicalGoal": "reconstruire un theme commun a partir de temoignages romans",
  "commonQuestion": "Quels changements avez-vous compris et quels points communs reliez-vous entre les participants ?",
  "character": {
    "id": "clara",
    "role": "etudiante",
    "languageId": "es",
    "context": "Valencia, chaleur estivale"
  },
  "constraints": {
    "maxWords": 24,
    "style": "temoignage oral court",
    "targetLanguageOnly": true,
    "transparentWordsPreferred": true
  }
}
```

## Donnees interdites

Interdit :

- texte apprenant ;
- reponse orale ou ecrite d'un etudiant ;
- `launchToken` ;
- token de session ;
- cookie ;
- `OPENAI_API_KEY` ;
- contenu `.env` ;
- donnees de session ;
- run complet ;
- `run_events` complets ;
- manifest complet si un resume court suffit ;
- donnees personnelles ;
- email ;
- userId ;
- brouillon non relu presente comme source publiee ;
- texte genere marque comme humain-reviewed ;
- contenu d'un autre cours non explicitement selectionne ;
- logs serveur ;
- stack traces ;
- couts ou secrets provider bruts.

Regle simple :

```txt
Si la donnee vient d'un apprenant, d'une session, d'un token, d'un secret ou d'un stockage runtime, elle ne part pas au provider.
```

## Schema de brouillon IA

Objet propose pour un brouillon V1.3-alpha :

```json
{
  "schema": "ic-lab-proto06-ai-roundtable-draft",
  "schemaVersion": "1.3-alpha",
  "draftId": "draft_local_...",
  "sourcePrototype": "proto06",
  "sourceVersion": "1.3-alpha",
  "sourceManifestId": "climate-roundtable-demo",
  "sourceManifestVersion": "1.0.0",
  "characterId": "clara",
  "languageId": "es",
  "generatedText": "Texte genere experimental...",
  "constraintsUsed": {
    "theme": "constats climatiques",
    "pedagogicalGoal": "reconstruction du theme commun",
    "commonQuestionIncluded": true,
    "maxWords": 24,
    "targetLanguageOnly": true,
    "transparentWordsPreferred": true,
    "previousTurnUsed": false
  },
  "safetyFlags": {
    "containsLearnerText": false,
    "containsApiKey": false,
    "sentToProvider": true,
    "storedOnServer": false,
    "writtenToRunEvents": false,
    "publishable": false
  },
  "modelLabel": "provider/model label visible",
  "providerLabel": "provider label visible",
  "generatedAt": "2026-07-03T00:00:00.000Z",
  "reviewStatus": "unreviewed-ai-draft",
  "publishable": false,
  "notes": "",
  "humanReview": null
}
```

Regles :

- `publishable` vaut toujours `false` a la creation ;
- `reviewStatus` vaut toujours `unreviewed-ai-draft` a la creation ;
- aucun brouillon ne devient manifest publie dans V1.3-alpha ;
- toute publication doit faire l'objet d'une mission separee et d'une revue humaine explicite.

## Architecture serveur-only

Principe technique :

```txt
Navigateur sandbox
-> endpoint serveur admin-only
-> provider IA cote serveur
-> reponse brouillon
-> affichage local dans le sandbox
```

Contraintes :

- aucun appel OpenAI depuis le navigateur ;
- endpoint serveur protege par role admin ;
- teacher et student refusés ;
- `store:false` obligatoire dans l'appel provider ;
- aucun `launchToken` accepte dans le payload sandbox ;
- aucune ecriture dans `run_events` ;
- aucune ecriture dans `runs.json` ;
- aucun stockage serveur en V1.3-alpha initiale, ou journal sandbox separe si decide plus tard ;
- aucun lien automatique avec une assignation etudiante.

Endpoints potentiels :

```txt
POST /api/admin/proto06/sandbox/generate-turn
GET  /api/admin/proto06/sandbox/context/:manifestId
```

`POST /api/admin/proto06/sandbox/generate-turn` :

- role : admin uniquement ;
- entree : contexte court autorise ;
- sortie : brouillon IA non publie ;
- stockage : aucun par defaut ;
- `store:false` cote provider ;
- logs : metadonnees non sensibles uniquement.

`GET /api/admin/proto06/sandbox/context/:manifestId` :

- role : admin uniquement ;
- retourne un resume court du manifest ;
- ne retourne pas de secret ;
- peut retourner les tours scenarises uniquement pour comparaison locale si le manifest est deja publie.

## Tests de securite attendus

### Acces roles

- admin : acces sandbox autorise ;
- teacher : `403` ;
- student : `403` ;
- utilisateur non connecte : `401`.

### Navigateur

- aucun fetch navigateur vers `api.openai.com` ;
- aucun secret dans le DOM ;
- aucun contenu `.env` visible ;
- aucun token visible ;
- aucun bouton publication ;
- aucun bouton assignation.

### Serveur

- endpoint admin-only ;
- refus des payloads contenant `launchToken`, `session`, `run`, `runEvents`, `studentText` ;
- appel provider avec `store:false` ;
- pas de log de prompt complet si celui-ci contient des donnees sensibles ;
- pas de log de cle API ;
- erreurs JSON lisibles.

### Runtime stable

- `index-1.2.3.html` intact ;
- flux Hub V0.9.9 -> Proto06 V1.2.3 intact ;
- fallback scenarise intact ;
- `runs.json` sans brouillon IA ;
- `run_events` sans texte genere complet ;
- `sessions.json` sans diff ;
- Prototype 06 stable non modifie.

### Donnees

- aucun texte apprenant envoye ;
- aucun manifest publie modifie ;
- aucun brouillon IA considere comme publie ;
- export local marque experimental.

## Relation avec le manifest publie

Le manifest publie peut servir de reference, pas de cible de modification directe.

Usages autorises :

- lire un resume court ;
- afficher les personnages ;
- afficher la consigne ;
- afficher la question commune ;
- comparer un tour scenarise humain avec un brouillon IA ;
- generer une variante brouillon ;
- exporter localement un brouillon experimental.

Usages interdits :

- reecrire le manifest publie ;
- marquer un brouillon IA comme `human-reviewed` ;
- ajouter automatiquement un step IA au manifest ;
- publier depuis le sandbox ;
- assigner une variante IA a un cours ;
- confondre manifest publie et brouillon IA.

Publication eventuelle :

```txt
brouillon IA
-> revue humaine
-> correction pedagogique
-> nouveau manifest ou nouvelle version
-> validation de securite
-> publication separee
```

## Separation avec le parcours etudiant

Visible :

- labels alpha ;

- avertissements permanents ;

Technique :

- endpoints admin-only ;
- pas de `runId` apprenant ;
- pas de `launchToken` ;
- pas de `run_events` ;

- pas de stockage dans les traces.

Documentaire :

## Proposition de premiere implementation limitee

Premiere implementation recommandee, strictement limitee :

1. Creer une page separee `sandbox-1.3-alpha.html`.
2. Afficher les badges permanents :
   - `Sandbox IA` ;
   - `Admin seulement` ;
   - `Experimental` ;
   - `Non publie`.
3. Charger localement ou via endpoint admin un resume court de `climate-roundtable-demo`.
4. Permettre de choisir un seul personnage.
5. Afficher les donnees qui seraient envoyees au provider.
6. Ajouter un bouton de generation desactive par defaut tant que les garde-fous ne sont pas confirmes.
7. Cote serveur, creer au maximum un endpoint admin-only de generation avec `store:false`.
8. Retourner un objet brouillon conforme au schema.
9. Ne rien stocker serveur dans la premiere version.
10. Autoriser uniquement un export local experimental.

Tests minimum avant validation :

- `node --check` des fichiers crees ;
- admin peut ouvrir le sandbox ;
- teacher/student refusés ;
- aucun appel OpenAI navigateur ;
- aucun secret DOM ;
- aucun diff `runs.json` / `sessions.json` ;
- aucun run_event ;
- V1.2.3 stable continue de charger `climate-roundtable-demo`.

## Definition de pret

V1.3-alpha sera prete pour une premiere implementation tres limitee quand les decisions suivantes seront confirmees :

- nom exact des fichiers sandbox ;
- endpoint serveur exact ;
- role d'acces ;
- provider autorise ;
- structure finale du prompt serveur ;
- strategie de non-stockage ;
- format d'export local ;
- procedure de revue humaine avant publication.

Jusque-la, le flux stable Hub V0.9.9 -> Proto06 V1.2.3 reste la reference apprenante.
